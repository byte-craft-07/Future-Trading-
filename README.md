# Future Trading

Future Trading is a Python-based multi-phase trading research system. It is built to experiment with market data, technical indicators, strategy signals, machine learning models, backtesting, intraday prediction, ensemble scoring, and dashboard-style outputs.

> Note: This project is for research and learning purposes only. It is not financial advice and should not be used for live trading without independent validation, risk controls, and broker-side safeguards.

## What This Project Does

- Downloads and prepares market data for analysis
- Builds technical indicators and engineered features
- Trains machine learning models for signal prediction
- Tests strategy ideas through backtesting
- Generates intraday and live-style trading signals
- Combines ML, LSTM, strategy, and sentiment inputs in an ensemble phase
- Produces plots, dashboards, logs, and signal files locally

## Project Structure

```text
python/trading_system/
|-- phase_a/   # Baseline data loading, cleaning, features, and ML model
|-- phase_b/   # Strategy rules, indicators, confluence logic, and reporting
|-- phase_c/   # Market structure signals and backtesting engine
|-- phase_d/   # Intraday pipeline, live signal engine, and dashboard helpers
`-- phase_e/   # Ensemble system, sentiment, LSTM models, and final dashboard
```

## Phase Overview

| Phase | Focus | Main Output |
| --- | --- | --- |
| Phase A | Data preparation, indicators, baseline model | Clean features and first ML model |
| Phase B | Strategy signals and confluence scoring | Strategy-enhanced model inputs |
| Phase C | Structure-based signals and backtesting | Backtest results and top strategies |
| Phase D | Intraday/live-style prediction system | Latest signal and dashboard output |
| Phase E | Ensemble model with sentiment and LSTM | Final combined trade signal |

## GitHub Safety

The repository is configured to avoid uploading sensitive or generated files. The following are intentionally ignored:

- raw and processed market data
- trained model files such as `.pkl`, `.keras`, `.h5`, `.onnx`
- generated plots and dashboard images
- logs, live signals, and backtest results
- local `.env` files, credentials, tokens, and editor settings
- Python cache folders such as `__pycache__`

Do not commit broker credentials, API keys, access tokens, account IDs, or private trading data. Use environment variables or a local `.env` file for secrets.

## Requirements

Install dependencies according to the phase you want to run. Common packages used by the project include:

```bash
pip install pandas numpy scikit-learn matplotlib yfinance pytz
```

Phase E may require additional deep learning dependencies such as TensorFlow/Keras.

## Basic Usage

Run commands from the `python/trading_system` directory:

```bash
cd python/trading_system
python phase_a/phase_a_main.py
```

Then continue phase by phase as needed:

```bash
python phase_b/phase_b_main.py
python phase_c/phase_c_main.py
python phase_d/phase_d_main.py
python phase_e/phase_e_main.py
```

Each phase may depend on artifacts generated by earlier phases. Generated data, models, plots, logs, and signals remain local and are not committed to GitHub.
